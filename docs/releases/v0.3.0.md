# WHPS v0.3.0 · Quality Verification and Versioned Site Adoption

**Distribution:** WHPS toolkit, Apache-2.0 (see `LICENSE` and `NOTICE`).  
**Previous published version:** [v0.2.1](https://github.com/joseferro-pt/wix-headless-production-system/releases/tag/v0.2.1), approved source `877736282def3631a3fad5d368e3098aadac040f`.  
**Contents:** merged WHPS-005 and WHPS-006, on top of the existing published foundation, WHPS-002/003 and WHPS-004.  
**Source verification:** the manual GitHub publisher appends the final exact-commit source SHA, matching CI URL, and publication-run evidence. This document alone does not attest that a tag or GitHub Release exists.

## What's new

### WHPS-005 · Reproducible testing and site QA

- Added a **committed npm package lock** for the standalone synthetic Astro reference, and changed GitHub CI to use `npm ci` instead of unpinned installation.
- Added `astro check` for TypeScript/Astro diagnostics and **Playwright Chromium browser tests** for optional React hydration, filtering, keyboard skip-navigation, viewport overflow, and reduced-motion behaviour.
- Added browser-based **axe-core automated accessibility checks**. Automated rules are not an audit of all WCAG requirements and cannot replace manual assistive-technology testing.
- Added versioned `site-qa-report.schema.json`, `scripts/evaluate-site-qa.mjs`, deliberately incomplete synthetic examples, tests and a site-owner QA evidence checklist. These validate **operator-reported records**, not external Wix state, evidence links or deployment permission.

### WHPS-006 · Pinned distribution and independent-site adoption

- Added `distribution/release-catalog.json` with **historical publicly verified** GitHub tags and source SHAs for v0.1.0 through v0.2.1.
- Added a **read-only public GitHub release verifier** checking exact SemVer tag, annotated tag object, resolved full commit SHA, and public matching GitHub Release. It neither authenticates the local machine nor certifies a website.
- Added an **offline, deterministic adoption/upgrade planner** that accepts source-pinned site metadata, compares selected toolkit components and rejects unknown releases, unsupported components, downgrades and implicit component removal. It never writes to the website or contacts Wix.
- Added versioned site-owned adoption record and planner-input JSON Schemas, synthetic failure tests, migration/rollback procedures, and an explicit distinction from the original `whps.lock.json` v2 bootstrap provenance.

## Adoption and migration impact

- **Existing v0.2.1 sites:** no automatic upgrade, changes to site files, schema migration, deployment or Wix service invocation. Verify the new toolkit release's exact annotated tag and SHA and review any selected component changes in the independent website repository.
- **New site QA and adoption records:** optional, versioned new formats. The original bootstrap `whps.lock.json` v2 remains authoritative for *which toolkit checkout generated the site*, regardless of subsequent site-local WHPS adoption.
- **Distribution mode:** clone/audit the **released source at an immutable tag plus exact SHA** and manually copy/adapt only reviewed generic components. No npm-published WHPS package, automated migration installer or website deployment is included.
- **Catalog freshness limitation:** because `distribution/release-catalog.json` only contains **already published releases**, the v0.3.0 tagged source intentionally does **not** include a preemptive v0.3.0 catalog entry. The offline planner therefore **cannot target v0.3.0** immediately from that snapshot; after independently verified publication, update the historical catalog through a **separate reviewed change**. The online verifier can verify v0.3.0 once published. Never spoof prior publication in the candidate catalog.
- **Backwards compatibility:** no deliberate changes to manifest `0.1.0`, bootstrap lock v2, resource-planner v1 or their public semantics. New operator records and QA gates are additive. A website's local dependencies, Wix SDK/app matrix and actual site quality require separate verification.

## Tested behaviour and limitations

GitHub CI exercises offline Node and Python contract tests, JSON Schema negative cases, boundary/security checks, provenance-aware new site bootstrapping on **synthetic** data, the locked Astro type/build checks, Chromium hydration/keyboard/responsive tests and axe-core automated rules. CodeQL runs on GitHub Actions, JavaScript/TypeScript and Python. Publication requires successful **push runs on the exact final main commit**, not merely earlier PR checks.

Limitations: no real Wix credentials, site identifiers, live app tests, member/payments flows, real SEO deployment, Wix-managed hosting, site-owner approval, site-release execution, complete WCAG certification or live website acceptance. Site reports are self-reported, not cryptographic evidence. Untested Astro 7 combinations remain outside the supported WHPS reference. Other operating systems and runtime versions are not guaranteed. Python dependency ranges and runner updates mean that not every external tool version is byte-for-byte pinned.

The open Dependabot major-version [PR #23](https://github.com/joseferro-pt/wix-headless-production-system/pull/23) proposes upgrading Astro 5 to 7 and **is not part of this release**. It needs a separately reviewed compatibility matrix and tests before merge.

## Publication protocol

1. Review and merge the **v0.3.0 preparation PR** after all PR validation/CodeQL checks pass.
2. Verify the new **exact `main` commit SHA** and complete, successful **push** runs for both `validate.yml` and `codeql.yml`, including source/boundary, npm `ci`, Astro diagnostics/build, Chromium and axe tests.
3. Obtain **separate explicit repository-owner approval to publish** that exact SHA and version. The instruction to prepare the candidate is not equivalent to approval to dispatch publication.
4. From the [manual publisher](../../.github/workflows/publish-release.yml) on **`main`**, enter `version=v0.3.0`, `source_sha=<the verified final main SHA>`, `approval=PUBLISH-v0.3.0`. Never use an earlier candidate SHA or dispatch after the branch moved.
5. After the successful workflow, independently confirm **annotated** `refs/tags/v0.3.0` resolves to the approved SHA; the public GitHub Release is non-draft, non-prerelease, and matches the approved source and publication evidence. Preserve all earlier tags.
6. Only after publication, reconcile release status and update the **historical catalog** with the independently verified v0.3.0 entry in a separate reviewed PR. Do not mark a candidate as published based on changelog, checks, or a local tag alone.
