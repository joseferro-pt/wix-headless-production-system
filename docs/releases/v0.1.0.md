# WHPS v0.1.0 — First Open-Source Toolkit Foundation

**Release type:** Initial 0.x toolkit release  
**License:** Apache-2.0  
**Manifest schema version:** `0.1.0` (separately versioned)  
**Release approval:** R05 reviewed merge into `main`, with CI passing for the exact merge commit  
**Release source commit:** resolved and recorded in the GitHub Release at publication

## Included

- Wix-generated handoff parser, original-prompt checksum preservation and atomic offline intake to an **independent** site directory.
- JSON Schema Draft 2020-12 manifest validation with mode-dependent contracts.
- Read-only ZIP inspection with bounded metadata checks and explicit unverified provenance caveats.
- Synthetic security and repository-isolation checks, deterministic regression tests and GitHub Actions CI.
- Generic operating protocols, authority model, site-repository blueprints, contribution/security policies, release governance and compatibility guidance.

## Tested platform

- Node.js 22, Python 3.12 and GitHub-hosted Ubuntu Linux (as evidenced by GitHub Actions on the published source revision).
- Python dependency: `jsonschema>=4.23,<5`. CI installs a currently satisfying version; dependency-locking is future work.

## Scope and important limitations

- This is an **early developer toolkit**, not a production-complete website generator.
- The CLI currently implements **only** Wix-generated-handoff offline intake. It does not create a Git repository, download the Wix source ZIP, provision Wix apps, connect to Wix, build or deploy a site.
- Wix's live Headless CLI/API/SDK integrations and any particular client website have **not** been end-to-end tested by WHPS CI.
- The ZIP auditor cannot independently prove Wix source provenance.
- The tracked-content guard is not comprehensive secret scanning and does not search all historical commits. An earlier historical site-specific report remains in old Git history; the current tree is project-neutral.
- This release contains no client code, Wix credentials, real Wix site IDs or Wix website deployment assets.

## Breaking changes and adoption

- First release, no previous published WHPS version to migrate from.
- Adopt by pinning the exact Git tag **and its resolved source commit** in the independent website repository. Do not track `main` for live websites.
- The manifest's own `schemaVersion: 0.1.0` is independent of the toolkit tag `v0.1.0`, even though these numbers currently coincide.
