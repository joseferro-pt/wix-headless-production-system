# WHPS v0.2.1 · Patch release candidate

**Status:** Candidate only. This document is **not** proof of a GitHub tag or published Release.
**Licence:** Apache-2.0, see source `LICENSE` and `NOTICE`.
**Approved prior version:** `v0.2.0`, published on 12 October 2026.
**Versioned schemas:** site manifest `0.1.0`, website adoption lock `2`, resource planner output `1`.

## Change summary

- **Bootstrap source integrity:** Reject a generating toolkit checkout with tracked, staged, unstaged, untracked or submodule changes; fail closed before creating a website directory.
- **Local repository attribution:** Require a configured Git `origin` matching an exact canonical WHPS HTTPS or SSH spelling; refuse missing, other-project or spoofed local URLs before writing the canonical source identity into the website adoption lock.
- **Regression coverage:** Synthetic negative tests for dirty checkout states, missing/unexpected origins, accepted canonical spellings and continued unverified-release semantics.
- **Governance:** Update README, Control Room, roadmap, adoption/compatibility contracts and historical R06 publication evidence.

## User-visible behaviour change

This compatible v2 adoption-lock schema is unchanged, but **bootstrap eligibility is more restrictive** than in v0.2.0: a dirty clone or an archive without Git origin configuration can no longer initialise a new site through the generator. Use a clean Git clone from the canonical WHPS repository; do not disable the guard to run modified local source. Forks must have a separately reviewed and explicit provenance policy; R06.1 does not claim they are canonical WHPS.

The local `origin` check is **not** independent proof that the remote source is authentic or that a release exists. Site maintainers must verify the exact tag and commit against the published GitHub Release before treating a generated workspace as release-pinned.

## Scope and limits

WHPS remains a site-agnostic, Apache-2.0 developer toolkit. No Wix resource was read or written; no real site repo, client configuration, secret, project file, site deployment, GitHub remote or published previous tag was altered. Production sites remain independent.

Testing targets Node.js 22, Python 3.12 and Git on GitHub-hosted Ubuntu with synthetic fixtures. Mac/Windows support, live Wix integration, malicious Git configuration tampering, private security intake and reproducible dependency locks are outside the verified scope.

## Publication requirements

Publication requires an explicit owner decision, final reviewed main SHA, successful exact-SHA `contracts` and CodeQL push runs, then a manual dispatch of `.github/workflows/publish-release.yml` with `v0.2.1`, exact source SHA and `PUBLISH-v0.2.1`. After successful execution, separately verify the immutable annotated tag and public GitHub Release. Add the final publication evidence to the current Control Room; do **not** overwrite this historical candidate snapshot or move earlier tags.
